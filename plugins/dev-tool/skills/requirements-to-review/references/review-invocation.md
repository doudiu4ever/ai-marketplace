# 各平台审核调用方式

各平台由本 skill 按用户确认的方式发起审核。**显式注入上下文的独立只读审核**与**不带显式上下文、直接审核未提交变更的独立审核**（如 `codex review --uncommitted`）为**平级选项**，由用户按需选择：

- **显式注入上下文**：把 [SKILL.md 的审核口径](../SKILL.md#审核口径) 连同需求、非目标、验收条件、实施进度、搬迁映射、简要修复记录及审核忽略区传给 reviewer，并明确告知测试脚手架的审核边界（仅聚焦误判通过、宿主机/仓库副作用及标准测试环境可执行性，不对非常规极端环境变量或特殊路径字符做防御性扩写）及忽略区仅作裁定输入、不做次生审查。
- **不带显式上下文**：依托 git 工作区内随代码同步更新的主体需求文档（含需求边界、验收条件、简要验证与审核记录、审核忽略区）与全部已暂存、未暂存和未跟踪变更一起被 reviewer 读取，无需额外 prompt 注入。仅能接收部分裸 diff、无法覆盖未跟踪文件（如新建需求文档与新增文件）的入口才仅用于补充检查。

复审时：带上下文方式在提示中附上上轮报告、逐项处理结果和最新忽略区（并标出先前已审过且未改动的生产代码范围）；不带上下文方式先更新 git 工作区内的主体需求文档摘要与 `## 审核忽略区`，再重新调用未提交变更审核。每轮原始审核细节与修复过程中的详细测试数据严格保存在 **git 仓库目录之外**，不进入未提交变更。两种方式下，即使本轮只更新了忽略区、代码未改动，也继续发起下一轮独立审核，直到 reviewer 明确报告无问题。

- **Codex**：先查 `codex review --help`。提供两种平级方式供用户选择：① `codex review --uncommitted`（不带自定义 prompt，直接审核全部已暂存、未暂存和未跟踪变更，依托 git 工作区内的主体需求文档与审核忽略区传递裁定上下文）；② `codex review -`（从标准输入传入完整提示，明确读取任务文档及全部已暂存、未暂存和未跟踪内容）。不假定自定义 prompt 可与 `--uncommitted` 组合，也不假定自动继承主会话上下文。
- **Claude Code**：允许委派时可用独立只读 reviewer 子代理传入完整审核上下文，不假定预装 `code-reviewer`。支持独立 CLI 时先查 `claude --help`，用 `claude -p` 并通过工具/权限限制写入，保留只读能力或提供完整材料；不虚构 `claude review`；禁止嵌套会话时改用允许的能力或手动独立会话，不绕过限制。
- **Antigravity (agy)**：无内置 `agy review`。前置确认按本机能力平级列出可选方式，注明是否涉及外部提供商/账号：① 宿主内置只读能力（允许委派时，用内置只读 `research` 子代理、无写工具的自定义只读子代理，或允许模型调用且真正委派独立只读 reviewer 的已安装 skill/子代理；仅在当前会话展开提示词的不算，跳过）；② 外部审核 CLI（如本机可用的 `codex review --uncommitted` 或 `codex review -`，两种方式平级可选，均须用户选定或预先授权后调用）；③ 独立 `agy -p` / `--print` 仅在允许嵌套会话且能强制工作区只读（如只读代理或无写权限配置）时使用（先查 `agy --help`，`--sandbox` 或仅传 diff 不算只读保护）；禁止嵌套时跳过 CLI。选手动方式，或缺少已授权的自动只读能力时，用手动独立会话，不绕过限制。
- **手动交互**：用户选择手动方式时，在对应客户端的独立审核会话或可用审核入口中发起审核，取得真实结果后继续。`/review` 等交互命令须以当前客户端支持情况为准，不能当作通用 shell 命令。
- 所选审核方式不可用或结果无法获得时，记录受阻并说明可选替代方式；切换用户明确指定的工具前取得确认。普通自查不能冒充独立审核，也不能因缺少某一客户端就认定当前客户端无法审核。
